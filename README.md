# ProtonVPN Scanner

ابزاری برای پیدا کردن سرورهای ProtonVPN که از نظر پینگ واقعاً در دسترس هستند، همراه با خروجی کانفیگ WireGuard.

## اجرا و تست روی macOS

### ۱. نصب Python 3.11

Kivy 2.3.0 (همان نسخه‌ای که در `buildozer.spec` استفاده شده) برای Python 3.11 و 3.12 بسته‌ی آماده دارد. Python 3.11 را توصیه می‌کنیم:

```bash
brew install python@3.11
```

اگر Homebrew را ندارید، ابتدا از [brew.sh](https://brew.sh) نصب کنید. روی Apple Silicon ممکن است لازم باشد مسیر Homebrew را به PATH اضافه کنید:

```bash
eval "$(/opt/homebrew/bin/brew shellenv)"   # Intel: /usr/local/bin/brew
```

یا از [python.org](https://www.python.org/downloads/) نسخه 3.11 را نصب کنید.

نسخه را بررسی کنید:

```bash
python3.11 --version   # باید 3.11.x نشان دهد
```

### ۲. دریافت پروژه و ساخت محیط مجازی

```bash
git clone <آدرس مخزن> ProtonVPN-scanner
cd ProtonVPN-scanner
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
```

از `python -m pip` استفاده کنید، نه `pip` تنها؛ چون `pip` ممکن است به Python دیگری تعلق داشته باشد و پکیج‌ها را جای اشتباه نصب کند.

`source .venv/bin/activate` را در هر پنجره ترمینال جدید دوباره اجرا کنید. وقتی محیط فعال است، ابتدای خط فرمان `(.venv)` دیده می‌شود و `which python` مسیری داخل `.venv/bin/` نشان می‌دهد. اگر این‌طور نبود، برنامه با Python سیستم اجرا می‌شود و خطای `No module named 'kivy'` یا `No module named 'requests'` می‌دهد.

اگر نصب موفق بود، آخرین خط خروجی باید با `Successfully installed` شروع شود و شامل `kivy-2.3.0` و `requests` باشد. اگر خطا دیدید، کل خروجی آن را نگه دارید.

### ۳. اجرای تست‌های واحد

```bash
python -m unittest -v
```

تست‌ها منطق برنامه (`scanner_core.py`) را بررسی می‌کنند و به رابط گرافیکی یا اینترنت نیاز ندارند. تست handshake با کلید خصوصی هم فقط داخل برنامه‌ی یک سرور محلی اجرا می‌شود و در حالت عادی رد می‌شود (skipped).

اگر می‌خواهید تست handshake را روی یک WireGuard واقعی اجرا کنید (مثلاً با `brew install wireguard-go wireguard-tools`)، سه متغیر را تنظیم کنید:

```bash
WG_TEST_PEER_PORT=<پورت سرور تست> WG_TEST_CLIENT_KEY=<کلید خصوصی کلاینت تست> WG_TEST_SERVER_PUB=<کلید عمومی سرور تست> python -m unittest -v tests.test_handshake
```

### ۴. اجرای برنامه

```bash
python main.py
```

1. دکمه **1. LOAD DATABASE** را بزنید. دیتابیس از GitHub دانلود و کش می‌شود.
2. نوع سرور (FREE / PREMIUM / ALL) و در صورت نیاز کشور یا قاره را انتخاب کنید.
3. **2. START SCAN (500)** را بزنید. این دکمه فقط پینگ را بررسی می‌کند. **قبل از هر اسکن VPN را خاموش کنید**، چون پینگ باید مستقیم اندازه‌گیری شود.
   - **SCAN WITH KEY** فعال می‌شود وقتی کلید خصوصی معتبر در کادر **WireGuard private key** باشد. این دکمه علاوه بر پینگ، با یک handshake واقعی WireGuard بررسی می‌کند که هر سرور کلید شما را می‌پذیرد یا نه. فقط سرورهای پذیرنده نمایش داده می‌شوند و روی کارتشان برچسب **key OK** است.
   - این بررسی همیشه WireGuard ساده است و کادر AmneziaWG در آن استفاده نمی‌شود.
4. هر بار ۵۰۰ سرور اسکن می‌شود. برای ادامه، **NEXT 500** را بزنید و VPN را برای آن دسته هم خاموش نگه دارید. تا وقتی فهرست تمام نشده، این کار را تکرار کنید. **RESET** اسکن را از اول شروع می‌کند.
5. روی هر سرور می‌توانید IP را کپی کنید (COPY IP)، کانفیگ WireGuard را کپی کنید (COPY WG) یا فایل `.conf` ذخیره کنید (SAVE .CONF).
   - **QR** یک کد QR از کانفیگ همان سرور روی صفحه نشان می‌دهد. با گوشی و برنامه‌ی WireGuard (Add tunnel > Create from QR code) از روی صفحه اسکن کنید. این کد کلید خصوصی شما را دارد؛ هر کسی که صفحه را ببیند می‌تواند آن را بردارد.
   - **COPY wg:// LINKS** لینک کانفیگ‌های سرورهای اسکن‌شده را کپی می‌کند، یک خط برای هر سرور؛ محدوده همان کشور یا قاره‌ای است که در اسپینرها انتخاب کرده‌اید (یا همه).
   - فرمت لینک همان فرمتی است که کلاینت‌هایی مثل Shadowrocket می‌خوانند: `wg://IP:51820?publicKey=…&privateKey=…&ip=…&dns=…&mtu=1280&udp=1&keepalive=25&obfs=amneziawg&obfsParam={json}#نام`. اگر کادر AmneziaWG خالی باشد، پارامترهای `obfs` نیستند.
   - برنامه‌های رسمی WireGuard این لینک را باز نمی‌کنند؛ برای آن‌ها از QR یا فایل `.conf` استفاده کنید.
6. برای خروجی گرفتن از ۱۵ سرور برتر، **EXPORT TOP 15 (.conf)** را بزنید. مسیر پوشه‌ی خروجی در نوار وضعیت نمایش داده می‌شود.

#### دیتابیس و کش

- بار اول، دیتابیس از GitHub دانلود و در فایل کش ذخیره می‌شود.
- تا یک ساعت، همان کش استفاده می‌شود و دانلود تازه انجام نمی‌شود.
- دکمه **RELOAD DATABASE** همیشه دیتابیس تازه را از GitHub می‌گیرد. اگر اینترنت قطع باشد، از کش قدیمی استفاده می‌شود.

#### مسیر فایل‌ها روی macOS

| مورد | مسیر |
| --- | --- |
| کش دیتابیس | `~/Library/Application Support/protonscanner/cache_github.json` |
| فایل‌های `.conf` | `~/Library/Application Support/protonscanner/wireguard/` |

در Finder می‌توانید از منوی **Go > Go to Folder** این مسیرها را باز کنید.

#### کلید خصوصی WireGuard

کلید عمومی هر سرور از دیتابیس خوانده می‌شود، اما کلید خصوصی باید از حساب ProtonVPN شما گرفته شود (بخش WireGuard در داشبورد Proton).

- اگر کلید خصوصی را وارد نکنید، در فایل‌ها `<PASTE_YOUR_PRIVATE_KEY>` قرار می‌گیرد و باید دستی جایگزین شود.
- اگر وارد کنید، کلید **به صورت متن ساده** داخل هر فایل `.conf` ذخیره یا خروجی گرفته می‌شود. این فایل‌ها را مثل رمز عبور نگه دارید و بعد از وارد کردن در WireGuard حذف کنید.
- **COPY WG** کانفیگ کامل (با کلید) را در کلیپ‌بورد سیستم قرار می‌دهد. بعد از استفاده کلیپ‌بورد را پاک کنید.
- بررسی کلید در اسکن، یک پیام handshake با کلید شما به هر سرور می‌فرستد. سرورهایی که جواب ندهند، یا کلید را نپذیرند، یا در دسترس نباشند؛ برنامه این سه حالت را از هم جدا نمی‌کند. برای جداسازی، یک سرور شناخته‌شده را با کلید دیگری امتحان کنید.

#### پنهان‌سازی AmneziaWG

کادر **AmneziaWG params** به‌طور پیش‌فرض با مقادیر یک کانفیگ AmneziaWG پر شده است (`Jc = 4`، `Jmin = 50`، `Jmax = 1000`، `S1 = 0`، `S2 = 0`، `H1 = 1` تا `H4 = 4`). بنابراین کانفیگ‌های COPY WG و SAVE .CONF و EXPORT به صورت AmneziaWG و با پسوند `_awg.conf` ساخته می‌شوند.

- اگر می‌خواهید WireGuard ساده بسازید، کادر را پاک کنید. در این حالت فایل‌ها پسوند `.conf` دارند.
- `H1` تا `H4` همان نوع پیام‌های استاندارد WireGuard هستند و `S1` و `S2` صفر است. پس تفاوت این مقادیر با WireGuard ساده فقط بسته‌های junk قبل از handshake است (`Jc`). اینکه این تفاوت برای عبور از مسدودسازی کافی باشد را من آزمایش نکرده‌ام.

- **مهم:** این پارامترها باید دقیقاً با تنظیمات سروری که به آن وصل می‌شوید یکی باشند. سرور باید AmneziaWG را اجرا کند؛ تنظیم سمت کلاینت به تنهایی کافی نیست. اگر سرور این را پشتیبانی نکند، handshake برقرار نمی‌شود و اتصال قطع می‌ماند.
- برای تست، همان سرور را با یک کانفیگ AmneziaWG کار‌کننده مقایسه کنید؛ اگر آن کانفیگ هم وصل نمی‌شود، مشکل از سرور یا پارامترهاست نه از برنامه.
- کلید خصوصی را داخل کادر پارامترها نچسبانید. برنامه خطوطی با کلید ناشناخته مثل `PrivateKey` را رد می‌کند.

### عیب‌یابی

- **`pip install` خطای build می‌دهد**: معمولاً یعنی برای نسخه Python شما wheel وجود ندارد. مطمئن شوید `python --version` نسخه 3.11 یا 3.12 را نشان می‌دهد و محیط `.venv` را با `python3.11` ساخته‌اید. اگر ابزارهای توسعه لازم بود: `xcode-select --install`.
- **چند نام با یک IP**: بعضی سرورهای Proton چند نام منطقی دارند (مثلاً RO#9، RO#31، RO#59) که روی یک میزبان با یک کلید عمومی هستند. برنامه این‌ها را یک بار اسکن می‌کند و نام‌های دیگر را داخل پرانتز کنار نام اصلی نشان می‌دهد، مثلاً `RO#9 (+3)`.
- **QR و AmneziaWG**: کادر AmneziaWG به‌طور پیش‌فرض پر است، پس QR هم خطوط AmneziaWG را دارد. برنامه‌ی WireGuard ساده ممکن است آن را نپذیرد؛ برای WireGuard ساده کادر را خالی کنید.
- **همه‌ی سرورها «dead» یا «fake» هستند**: VPN را کامل خاموش کنید. اگر برنامه‌ی Proton یا یک پروفایل VPN سیستمی فعال است، ممکن است ترافیک همچنان از تونل عبور کند. گزینه‌های Kill Switch یا Always-on را هم بررسی کنید.
- **سرورهای زیر ۱۰۰ میلی‌ثانیه حذف می‌شوند**: این کار عمدی است، چون پینگ‌های خیلی کم معمولاً واقعی نیستند.
- **macOS اجازه‌ی شبکه می‌خواهد**: برنامه فقط اتصال خروجی برقرار می‌کند و معمولاً پیامی نمی‌بیند. اگر پرسید، آن را بپذیرید.
- **دیتابیس لود نمی‌شود**: اینترنت یا فیلترینگ را بررسی کنید. اگر کش قدیمی وجود داشته باشد، برنامه از آن استفاده می‌کند.

## ساختار پروژه

| فایل | کاربرد |
| --- | --- |
| `main.py` | رابط گرافیکی Kivy |
| `scanner_core.py` | منطق بدون وابستگی به Kivy: دیتابیس، فیلترها، پینگ، کانفیگ WireGuard |
| `tests/test_scanner_core.py` | تست‌های واحد |
| `buildozer.spec` | تنظیمات ساخت APK برای اندروید |
| `requirements-dev.txt` | وابستگی‌های اجرا و تست روی دسکتاپ |

## ساخت APK

APK با GitHub Actions ساخته می‌شود: workflow با نام `Build Android APK` را به صورت دستی اجرا کنید. بعد از پایان اجرا، فایل `ProtonScanner-APK` را از بخش **Artifacts** همان اجرا دانلود کنید. پوشه `tests/` از APK حذف شده است.
